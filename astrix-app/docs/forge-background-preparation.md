# Forge background preparation

Build Forge starts a dedicated module Web Worker after receiving a verified Forge Loader handoff. It prepares the selected element, tuning objective and explicit Super first, then a bounded set of alternatives. Preparation does not populate the displayed recommendation or alter a live Guardian. Generate Max Loadout retrieves the matching result and repeats coherence and transfer-preflight validation before opening review.

The worker retains the established sequence: subclass composition, owned-weapon ranking, provisional armour mods, Artifact matching, Artifact-aware weapon ranking, final mods, final Artifact matching, coherence/preflight and recommendation-only weapon advice. The Artifact selection module is unchanged. Selecting a verified Super constrains that candidate's Super options; unsupported hashes and incomplete Forge Loader inputs are rejected.

One job runs at a time. The queue is limited to 12 variants; completed-key bookkeeping to 32. The client caches at most four results and 8 MiB of serialized result payloads. The combination scorer streams candidates, retains its existing beam width and limits the scoring memo to 512 entries in worker mode. Scoring weights, ordering and tie-breaks are unchanged. These bounds limit retained computation data, not total browser heap or the size of Bungie's verified input snapshot.

A new build snapshot or season invalidates the worker and cached results. Late messages from an old worker or revision are discarded. An uncached explicit Generate request interrupts unrelated speculative work. Worker errors and a 120-second request timeout leave the source build intact and allow retry. Leaving the page terminates preparation. Browsers without module Worker support report preparation unavailable; expensive computation does not fall back onto the UI thread.

Preparation begins on Build Forge after the Forge Loader handoff, not before armour selection. At most twelve alternatives are warmed, rather than the full Cartesian product. Other supported choices are computed on demand. Input readiness gates remain: absent Bungie data cannot be replaced by a fabricated build. The worker is browser-local, not a new Cloudflare service; no authentication tokens are passed to it and no equip/transfer API is called.

Validation: deterministic standard/bounded scoring equivalence (including Prismatic), an actual Node worker-thread run of the worker handler and full sequence, explicit-Super and Exotic-ability preservation, immutable source snapshots, cache limits, stale-result rejection, request prioritization and worker-error retry. Existing Artifact provenance/selection and full PARADOX gates remain required. These synthetic tests do not replace authenticated Guardian visual QA or measurements on a full live inventory.
